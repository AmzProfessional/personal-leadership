# Калібровка селекторів

## Навіщо це потрібно

Розмітка amzlms.com невідома цьому скілу наперед. `config/selectors.default.json`
містить не готові селектори, а **підказки**: набір можливих підписів полів
українською та англійською. Резолвер пробує їх по черзі — від найнадійніших
способів до найризикованіших:

1. `css` — точний CSS-селектор із конфігу;
2. `testId` — `data-testid` / `data-test` / `data-qa`;
3. `label` — Playwright `getByLabel`, працює коли є `<label for="...">`;
4. `placeholder`;
5. `role` + `name` — доступна назва (найкраще для кнопок);
6. `anchored` — знайти видимий підпис і взяти найближчий контрол поруч.

Останній спосіб — запасний. Він рятує на формах без `label for`, але саме він
може помилитися. Тому мета калібровки — щоб важливі поля знаходилися
способами 1–5, а не 6.

## Як калібрувати

```bash
node scripts/discover.mjs --stage question
```

Скрипт відкриє браузер, дочекається входу, натисне «Створити тест», потім
«Додати питання», і збереже `discovery-report.json`.

У консолі буде зведення:

```
Розпізнані поля:
  ✓ title                  label:Назва тесту
  ✓ description            anchored:Опис тесту -> textarea
  ✗ passingScore           — НЕ ЗНАЙДЕНО
```

Читати так:

- `✓ label:...` або `✓ testId:...` — добре, нічого не роби.
- `✓ anchored:...` — працює, але тримається на верстці. Якщо поле важливе
  (назва, текст питання, варіанти відповідей), краще замінити на точний CSS.
- `✗ НЕ ЗНАЙДЕНО` — обов'язково пропиши селектор, інакше поле буде пропущене
  або запуск впаде.

## Де взяти точний селектор

У `discovery-report.json` є секції `steps.createTestForm` і
`steps.questionEditor`. Кожен контрол описаний так:

```json
{
  "tag": "input",
  "type": "number",
  "label": "Прохідний бал",
  "placeholder": null,
  "testId": null,
  "formControlName": "passingScore",
  "id": "f-pass",
  "css": "#f-pass"
}
```

Поле `css` — готовий селектор. Кнопки лежать у `buttons` з їхнім текстом.

## Куди це записати

Створи `config/selectors.json` (він перекриває `selectors.default.json` по
одному полю, решта лишається зі стандартних підказок):

```json
{
  "fields": {
    "passingScore": { "css": "#f-pass" },
    "timeLimit": { "css": "input[formcontrolname='duration']" },
    "optionRow": { "css": ".answer-row" },
    "saveQuestionButton": { "role": "button", "name": ["Зберегти питання"] }
  }
}
```

Пріоритет: значення з `selectors.json` повністю замінює однойменне поле зі
стандартного файлу. Тобто якщо пишеш `{"css": "..."}`, підказки `label` для
цього поля більше не використовуються — за потреби перелічи їх поруч.

## Поля, які варто перевірити найуважніше

| Поле | Чому важливе |
| --- | --- |
| `optionRow` | Визначає, як рахуються рядки відповідей. Помилка тут — і варіанти поїдуть не в ті рядки. |
| `optionCorrectToggle` | Позначка правильної відповіді. Якщо не знайдеться, тест створиться без правильних відповідей. |
| `addOptionButton` | Без неї не додати більше варіантів, ніж форма показує спочатку. |
| `questionTypeSingle` / `questionTypeMultiple` | Якщо не знайдуться, всі питання отримають тип за замовчуванням. |
| `saveQuestionButton` | Якщо співпаде з іншою кнопкою, питання не збережеться. |

## Корисні додаткові ключі

- `nth` — брати N-й збіг, якщо селектор знаходить кілька елементів:
  `{ "css": ".form-control", "nth": 2 }`
- `anchor` — додатковий текст для запасного пошуку, коли підпис поля
  відрізняється від того, що в `label`.
- `controlSelector` — чим саме шукати контрол біля підпису, якщо це
  нестандартний віджет: `{ "label": "Категорія", "controlSelector": ".my-select" }`
- `maxControls` — скільки контролів у контейнері ще вважається «одним полем»
  (за замовчуванням 3). Підвищувати варто рідко: саме це обмеження не дає
  підпису без сусіднього поля причепитися до чужого інпуту.
