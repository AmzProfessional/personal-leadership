# Формат файлу з питаннями

Два формати на вибір. Markdown — для написання й правок руками, JSON — коли
питання генеруються програмно або приходять з іншої системи. Обидва
перетворюються на одну й ту саму внутрішню структуру, тож поводяться однаково.

## Markdown

### Frontmatter

Блок між `---` на початку файлу. Ключі можна писати українською або
англійською — обидва варіанти розпізнаються.

| Значення | Ключі, які приймаються | Обов'язково | За замовчуванням |
| --- | --- | --- | --- |
| Назва тесту | `Назва тесту`, `Назва`, `title`, `name` | так | — |
| Опис | `Опис тесту`, `Опис`, `description` | ні | порожній |
| Категорія | `Категорія`, `category` | ні | не вибирається |
| Департаменти | `Департаменти`, `Департамент`, `departments` | ні | не вибирається |
| Прохідний бал | `Прохідний бал`, `passing_score`, `passingScore` | ні | `80` |
| Час (хв) | `Час`, `time`, `time_limit` | ні | `auto` |
| Хвилин на питання | `minutes_per_question` | ні | `1` |

Департаменти — список через кому: `Департаменти: Sales, Support`. Квадратні
дужки теж приймаються: `[Sales, Support]`.

`Час: auto` рахує `кількість питань × хвилин на питання`. Це стандарт
«одна хвилина на одне питання». Щоб задати фіксований час, напиши число:
`Час: 25`.

### Питання

Кожне питання починається із заголовка `##`. Нумерація на початку заголовка
прибирається, тому можна вставляти готовий пронумерований список:

```markdown
## 7. Який показник свідчить про перевантаження команди?
```

стане питанням `Який показник свідчить про перевантаження команди?`.

Якщо текст питання довгий, наступні рядки до першого варіанта відповіді
приєднуються до тексту:

```markdown
## Керівник помічає, що команда систематично не встигає в терміни.
Які дії будуть доречними в першу чергу?
- [x] Переглянути обсяг і пріоритети завдань
- [ ] Ввести штрафи за зрив дедлайнів
```

### Варіанти відповідей

```markdown
- [x] Правильний варіант
- [ ] Неправильний варіант
```

Замість `x` приймаються також `X`, `✓`, `✔`. Порядок варіантів у файлі
зберігається — у LMS вони будуть у тому ж порядку.

### Тип питання

Рядок `type:` одразу після заголовка, до першого варіанта:

```markdown
type: single      # одна вірна відповідь
type: multiple    # багато вірних відповідей
```

Синоніми: `одна`, `single`, `radio` / `багато`, `multiple`, `checkbox`.
Український ключ `тип:` теж працює.

Якщо `type:` не вказано, він визначається за кількістю позначених
відповідей: одна → `single`, більше однієї → `multiple`. Це майже завжди
правильно, тому писати `type:` варто лише в одному випадку — коли питання
задумане як «багато вірних відповідей», але зараз правильна тільки одна.

### Пояснення

Рядок, що починається з `>`. Показується користувачеві після відповіді.

```markdown
> Пояснення: перевантаження видно за зростанням часу проходження задач.
```

Префікс «Пояснення:» / «Explanation:» прибирається — його можна писати або
не писати. Кілька рядків `>` поспіль об'єднуються в один текст.

Пояснення не обов'язкове, але його відсутність дає попередження у звіті:
для навчального тесту пояснення — це половина цінності.

## JSON

Той самий тест у JSON:

```json
{
  "title": "Персональне лідерство — модуль 1",
  "description": "Підсумкова перевірка знань",
  "category": "Управління командою",
  "departments": ["Sales", "Support"],
  "passingScore": 80,
  "timeLimit": "auto",
  "questions": [
    {
      "text": "Що таке персональне лідерство?",
      "type": "single",
      "explanation": "Починається з управління собою.",
      "options": [
        { "text": "Здатність керувати собою", "correct": true },
        { "text": "Формальна посада", "correct": false }
      ]
    }
  ]
}
```

Приймаються також `question` замість `text`, `answers` замість `options`,
`isCorrect` замість `correct`. Файл із розширенням `.json` парситься як JSON
автоматично.

## Що перевіряється до відкриття браузера

Ці умови зупиняють запуск:

- немає назви тесту;
- у файлі жодного питання;
- порожній текст питання;
- менше двох варіантів відповіді;
- порожній текст варіанта;
- два однакові варіанти в одному питанні;
- жодної позначеної правильної відповіді;
- `type: single`, але позначено кілька правильних.

Ці умови лише попереджають:

- питання без пояснення;
- `type: multiple` з однією правильною відповіддю;
- два питання з однаковим текстом.
